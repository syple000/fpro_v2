# 数据语义假设与补充审计清单

审计日期：2026-09-08。审计代码基线：`a8b8dcd`。QMT 下载分钟线使用固定结束标签。
2026-09-10 更新：AUD-001、AUD-002 已修复，AUD-003 的接收回放用途已移除，AUD-005 部分修复；
其余条目仍待处理。

检查范围：行情接入、协议、接收与同步、Parquet 压缩、行情适配、清洗与交叉校验，以及
回测时钟、撮合、费用、公司行动、证券身份和策略。重点是把未经核实的外部语义当成事实的
地方，也记录检查中发现的相关实现缺陷；不代表已经穷尽项目所有风险。

共 12 项：8 项已有本地数据、构造复现或规则对照支持的问题，4 项仍待核实的契约。
构造复现只证明条件成立时的代码行为，不能证明真实数据已触发；外部规则只适用于已核实的
市场和生效日期。已明确声明的简化模型另列在最后，不混算成未验证缺陷。

## 已调整：历史分钟线与推送事件分开

2026-09-10 起，`QmtAdapter.intraday_bars()` 只读取下载表 `qmt.intraday`，按固定结束标签计算区间。
原始推送 `qmt.bars` 不再进入历史查询、撮合或估值。`bar_availability` 参数和接收回放分支已移除，
运行元数据记录 `qmt.intraday_bars="downloaded"`。

推送结束标签曾从 `handlebar` 社区讨论推断，但没有盘中实测收线证据；现在历史读取不依赖该推断。
原始推送保留在实时接口，不能仅凭区间结束就宣称其 OHLCV 完整。

## 一、已有证据的问题

### AUD-001：停牌字段被当成单个、双位小时区间（P1，已修复）

- 位置：[adapters.py](../src/market_data/adapters.py) `TushareAdapter.suspensions()`，约 609 行；
  [detector.py](../src/data_cleaning/detector.py) 的停牌检测约 1029 行。
- 假设：`suspend_timing` 总是一个 `HH:MM-HH:MM`。代码只提取前两个时间，清洗检测也没有
  校验完整时间段。[Tushare 字段说明](https://tushare.pro/document/2?doc_id=214)没有保证此限制。
- 当前 Manifest 真实记录：`301025.SZ / 2021-07-19 / S` 的值为
  `09:30-09:40,09:40-09:50`，原适配器在 09:45 返回 `suspended=False`。
  `600421.SH / 2026-06-01 / S` 的值为 `9:30-9:40`，09:35 查询抛出停牌格式错误。
- 影响：第二段停牌可能被放行成交；单数字小时格式会中断回测。
- 修复：清洗与查询共用完整解析函数，支持一位/两位小时、可选秒及逗号分隔的全部时段。
  各段按 `[开始, 结束)` 判断；任一已开始的停牌段仍有效就禁止成交，空隙及全部结束后恢复。
  坏片段整体拒绝，未来段不提前改变状态，无覆盖证明时仍保留未知。
- 验证：以上真实格式的边界、空隙、相邻/重叠/乱序区间、坏后缀及全日复牌同行均有回归测试；
  撮合集成测试确认第二段停牌及单数字小时停牌不会放行。只读查询当前 Manifest 的两条真实记录，
  分别确认 09:45/09:35 为停牌、09:50/09:40 为恢复。补扫全部 325 种原始时段，发现带秒的真实
  格式（如 `839680.BJ / 2021-11-15 / 09:34:21-09:44:21,09:46:15-09:56:15`），也已覆盖。
  修复后全套 609 项测试、Ruff、Pyright 通过。
- 原始数据边界：扫描仍发现 3 种共 4 条非正区间（`09:30-09:30`、
  `09:33-09:43,11:10-11:10`、`13:00-9:30`）。清洗会报告，查询会明确报错；
  本次没有猜测其正确时间或改写生产数据。

### AUD-002：现行行业分类被当作历史时点分类（P1，已修复：限制历史支持范围）

- 位置：[adapters.py](../src/market_data/adapters.py) `industry()`，约 1365 行；
  [sync.py](../src/tushare_data/sync.py) 行业同步约 499 行。
- 假设：`index_member_all.in_date` 也证明返回的行业分类版本在该日已经存在。
  当前只按成员进出日期过滤，没有行业标准版本。
- 本地记录把 `000523.SZ` 的“美容护理”追溯到 1993-11-08，把 `000035.SZ` 的“环保”追溯到
  1994-04-08；实际查询 2010-01-04 10:00，原适配器返回这两个一级行业。
- [申万 2021 版说明](https://wxweb.swsresearch.com/swsreport/2021_08/328340.pdf)明确当次新增
  美容护理，并把环保从公用事业拆出单列。本次取得该官方 PDF 的搜索索引正文，直接下载受限。
- 影响：历史行业选股、行业中性化可能使用后来形成的分类；“按现行分类回溯”不能标成
  “当时可见分类”。
- 修复：内置 Tushare 行业源只支持 `2021-08-02 09:25`（上海时间）起，更早查询明确报缺少
  旧版历史成员分类。官方说明记载 2021-07-30 推出、7 月 31 日公告，因此保守采用公告后下一
  交易日盘前作为支持起点；这是项目可见性约定，不是供应商到达时刻或指数调整日期。
  原始 `in_date/out_date` 保持不变；支持起点后仍有效的早期成员不会被误删；自定义历史
  适配器不受该限制。未增加版本配置或从现行行业反推旧行业。
- 证据边界：当前 [`index_member_all`](https://tushare.pro/document/2?doc_id=335) 没有标准
  版本参数；[`index_classify`](https://tushare.pro/document/2?doc_id=181) 的旧版行业目录也
  不能恢复当时的股票成员。此修复阻止已证实的分类出现前穿越，不代表补齐了旧版数据或验证了
  所有供应商历史修订、实际到达时刻；支持范围内仍采用原成员区间。
- 验证：新增 20 项回归，覆盖三层级早期拒绝、上海/UTC 边界、早期纳入成员保留、未来成员
  隔离与进出切换、自定义历史来源不受限。只读查询当前 Manifest，两只真实证券的 2010 查询
  已明确拒绝，支持边界之后仍正常返回。全套 629 项测试、相关 Ruff、Pyright 通过。

### AUD-003：实时压缩只保留最后版本（接收回放用途已移除）

- 位置：[schemas.py](../src/qmt_receiver/schemas.py)、[store.py](../src/parquet_store/store.py)。
- 2026-09-08 构造复现：相同 `(code, period, event_time)` 的两个版本压缩后只剩最后一行，
  无法重建两个接收时刻之间的可见状态。
- 2026-09-10 调整：移除历史查询和回测的 `received` 模式，实时表只承担快照存档。

### AUD-004：越界恢复主动跳过仍可读取的序号（P1，构造复现）

- 位置：[receiver.py](../src/qmt_receiver/receiver.py) `_probe_available_sequence()`，108 行。
- 实现：先请求 `oldest_seq - 1`，失败后请求 `oldest_seq + 1`，未尝试 `oldest_seq`。
- 固定缓存边界 `oldest=100, latest=200` 的内存复现，请求序列为 `1 → 99 → 101`，
  返回从 101 开始；100 仍在缓存，却被跳过。这是实现错误，不依赖 QMT Bar 标签语义。
- 影响：把本可恢复的数据也算入丢失，可能漏掉某个 Bar 的唯一版本。
- 应验证：静止边界、移动边界、恰好追到最新以及 agent 重启场景；不要只覆盖边界一直移动的测试。

### AUD-005：查询成功被等同于请求区间已完整同步（P1，部分修复）

- 位置：[sync.py](../src/qmt_receiver/sync.py) `sync_daily()`、`sync_intraday()`。
- 2026-09-10 修复：历史日线和分钟线只同步上海时区前一自然日及以前的数据；当天和未来日期
  保持待同步。响应遗漏的证券不登记完成，后续请求会重试。
- 验证：`test_sync.py` 覆盖上海时区跨日、未来日期、force 边界、后续补全及响应遗漏证券。
- 剩余边界：响应包含证券但只给出部分 K 线，或返回空列表时，仍无法仅凭响应证明该区间完整。
  需要结合上市、停牌、交易日历验证；旧 checkpoint 需对受影响区间使用 force 重新同步。

### AUD-006：收盘集合竞价仍按连续交易 Bar 撮合（P1，规则对照与构造复现）

- 位置：[clock.py](../src/backtest/clock.py) 35 行、`_intraday_events()`；
  [engine.py](../src/backtest/engine.py) `_process_bar()`；
  [broker.py](../src/backtest/broker.py) `match_bar()`。
- 假设：13:00–15:00 的分钟 Bar 都可以按区间起点开盘价成交，没有收盘集合竞价阶段。
- 构造验证：14:57 开始的 Bar，在其它状态及数量合法时允许成交 100 股，成交时点按 14:57 记录。
  [上交所通知](https://big5.sse.com.cn/site/cht/www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20180806_4607055.shtml)
  明确股票自 2018-08-20 起在 14:57–15:00 采用收盘集合竞价。
- 影响：可能在竞价完成前虚构成交、价格和持仓变化。
- 应验证：真实 14:56–15:00 数据及竞价前后订单，区分交易所、日期与频率。
  不能把全部历史交易时段统一截到 14:57，也不能因保留 15:00 收盘 Bar 就宣称竞价撮合已正确。

### AUD-007：已知无涨跌幅限制被等同于允许市价申报（P1，规则对照与构造复现）

- 位置：[broker.py](../src/backtest/broker.py) `_executable_quantity()`、`_known_price_limits()`；
  [trading_rules.py](../src/backtest/trading_rules.py) 34 行。
- 假设：`price_limit_status="unlimited"` 加不停牌就允许成交。引擎目前只提供市价数量订单，
  却没有另行核对该市场、该日是否接受这种申报。
- 构造深圳证券、连续竞价时点和明确无限制状态，代码允许 100 股成交。
  [深交所 2026 版规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)
  第 3.3.5 条要求市价申报用于有价格涨跌幅限制证券的连续竞价；第 10.9 条规定该版自
  2026-07-06 生效。本项规则冲突仅按该已核实版本判断，不倒推所有历史版本。
- 影响：可能在不接受市价申报的交易日生成成交。它不同于 BT-020 的未知状态误放行。
- 应验证：深圳新股无限制日市价单拒绝；其它市场、历史日期单独核实适用规则。

## 三、不应混为未经验证缺陷的已声明模型

- 日线 16:05 可见、仅有公告日期时下一交易日 09:25 可见：是明确选择的回测可见性规则，
  不是承诺数据源在该秒实际发布。要做真实接收回放仍须另存原始到达时间。
- 滑点、容量、红利税近似、碎股舍入、显式退市核销：已声明的模型范围；没有新证据时不把
  “不够精细”写成未经验证的外部事实。
- QMT 股票历史量额、除权换算已有项目实机交叉验证记录；证据只覆盖记录的样本和接口，
  不自动推广到所有产品、周期和客户端版本。
- 稳定 `sid` 要求外部可信更码表；没有表时不猜更码关系，属于明确依赖。

建议先处理会放行错误成交或改变历史可见性的 AUD-001、003、006、007，随后补齐采集完整性
与行业版本。AUD-009、010、011 应共用一次盘中原始采样验证。以上事项没有在本轮顺带实现，
后续修复应继续逐项验证、独立提交。
