# 数据语义假设与补充审计清单

审计日期：2026-09-08。代码基线：`a8b8dcd`。本轮只修正 QMT 推送的默认时间标签，
以下新增事项仅记录，尚未修复。

检查范围：行情接入、协议、接收与同步、Parquet 压缩、行情适配、清洗与交叉校验，以及
回测时钟、撮合、费用、公司行动、证券身份和策略。重点是把未经核实的外部语义当成事实的
地方，也记录检查中发现的相关实现缺陷；不代表已经穷尽项目所有风险。

共 12 项：8 项已有本地数据、构造复现或规则对照支持的问题，4 项仍待核实的契约。
构造复现只证明条件成立时的代码行为，不能证明真实数据已触发；外部规则只适用于已核实的
市场和生效日期。已明确声明的简化模型另列在最后，不混算成未验证缺陷。

## 本轮已修正：QMT 推送默认结束标签

`QmtAdapter` 与 `DataReader` 的实时标签默认值均从 `start` 改为 `end`，原始时间戳不平移，
只由适配器计算区间起止。显式 `start` 仍用于调用方已确认的其它采集口径。

依据是[迅投社区的 5 分钟逐 K 线讨论](https://www.xuntou.net/forum.php?mod=viewthread&tid=939)：
开盘后 `handlebar` 已运行，对应 Bar 的标签为 09:35。将其用于 `subscribe_quote` 仍是
跨接口推断，并非当前客户端实测。此前盘后四个 1m/5m 订阅观察约 90 秒，没有收到 Bar。
相关回归 71 项、全仓库 522 项测试通过，改动 Python 范围 Ruff、Pyright 通过。

## 一、已有证据的问题

### AUD-001：停牌字段被当成单个、双位小时区间（P1，本地数据复现）

- 位置：[adapters.py](../src/market_data/adapters.py) `TushareAdapter.suspensions()`，约 609 行；
  [detector.py](../src/data_cleaning/detector.py) 的停牌检测约 1029 行。
- 假设：`suspend_timing` 总是一个 `HH:MM-HH:MM`。代码只提取前两个时间，清洗检测也没有
  校验完整时间段。[Tushare 字段说明](https://tushare.pro/document/2?doc_id=214)没有保证此限制。
- 当前 Manifest 真实记录：`301025.SZ / 2021-07-19 / S` 的值为
  `09:30-09:40,09:40-09:50`，原适配器在 09:45 返回 `suspended=False`。
  `600421.SH / 2026-06-01 / S` 的值为 `9:30-9:40`，09:35 查询抛出停牌格式错误。
- 影响：第二段停牌可能被放行成交；单数字小时格式会中断回测。
- 应验证：直接使用这些真实行，覆盖各段边界、段间空隙、相邻区间和小时格式，不能只增加
  一个更宽松的正则而仍丢弃后续区间。

### AUD-002：现行行业分类被当作历史时点分类（P1，本地数据与源标准对照）

- 位置：[adapters.py](../src/market_data/adapters.py) `industry()`，约 1365 行；
  [sync.py](../src/tushare_data/sync.py) 行业同步约 499 行。
- 假设：`index_member_all.in_date` 也证明返回的行业分类版本在该日已经存在。
  当前只按成员进出日期过滤，没有行业标准版本。
- 本地记录把 `000523.SZ` 的“美容护理”追溯到 1993-11-08，把 `000035.SZ` 的“环保”追溯到
  1994-04-08；实际查询 2010-01-04 10:00，原适配器返回这两个一级行业。
- [申万 2021 版说明](https://wxweb.swsresearch.com/swsreport/2021_08/328340.pdf)明确当次新增
  美容护理，并把环保从公用事业拆出单列。本次取得该官方 PDF 的搜索索引正文，直接下载受限。
- 影响：历史行业选股、行业中性化可能使用后来形成的分类；“按现行分类回溯”不能标成
  “当时可见分类”。
- 应验证：按年份取得分类标准及成员表，明确使用历史版本还是现行版本回溯，并验证版本切换。

### AUD-003：实时压缩删除接收版本，破坏过去可见性（P1，构造复现）

- 位置：[schemas.py](../src/qmt_receiver/schemas.py) 190 行；
  [store.py](../src/parquet_store/store.py) `_deduplicate_primary_key()`；
  [receiver.py](../src/qmt_receiver/receiver.py) 66 行。
- 假设：相同 `(code, period, event_time)` 只需保留最终版本。压缩按 `received_at` 留最后一行，
  Receiver 初始化还会自动压缩实时表；这与 `received` 模式要求重建过去可见版本冲突。
- 内存复现：同一个 Bar 两个接收版本，压缩前 2 行、压缩后 1 行。在两个接收时刻之间查询，
  可见行数从 1 变 0，只保留 `seq=2`。没有本机多版本推送样本，未确认真实触发范围。
- 影响：同一次回测可能因之后执行了压缩而丢失当时已经收到的价格。
- 应验证：压缩前后逐时点比较 `received` 查询，而非只比较最终价格。需要保留事件版本，
  或明确实时表仅是最终快照、不能承担接收回放。

### AUD-004：越界恢复主动跳过仍可读取的序号（P1，构造复现）

- 位置：[receiver.py](../src/qmt_receiver/receiver.py) `_probe_available_sequence()`，108 行。
- 实现：先请求 `oldest_seq - 1`，失败后请求 `oldest_seq + 1`，未尝试 `oldest_seq`。
- 固定缓存边界 `oldest=100, latest=200` 的内存复现，请求序列为 `1 → 99 → 101`，
  返回从 101 开始；100 仍在缓存，却被跳过。这是实现错误，不依赖 QMT Bar 标签语义。
- 影响：把本可恢复的数据也算入丢失，可能漏掉某个 Bar 的唯一版本。
- 应验证：静止边界、移动边界、恰好追到最新以及 agent 重启场景；不要只覆盖边界一直移动的测试。

### AUD-005：查询成功被等同于请求区间已完整同步（P1，构造复现）

- 位置：[sync.py](../src/qmt_receiver/sync.py) `sync_daily()` 118 行、`sync_intraday()` 166 行。
- 假设：下载未抛异常、查询返回成功，就能给每个请求证券登记整个日期范围已完成；没有区分
  响应遗漏、已确认无行情，以及盘中尚未结束的区间。
- 内存复现：请求两只股票，源只返回 `000001.SZ` 一行，两只都被标记完成。第二次同步返回
  0 行且没有重新下载。只确认校验缺口，不认定真实空响应一定是漏数据。
- 影响：不完整日线、分钟线可能长期不再补齐。
- 应验证：结合上市、停牌、交易日历核对缺失，并覆盖部分证券遗漏、盘中当天和未来结束日期。
  无法证明完成的范围应保持待补状态。

### AUD-006：收盘集合竞价仍按连续交易 Bar 撮合（P1，规则对照与构造复现）

- 位置：[clock.py](../src/backtest/clock.py) 35 行、`_intraday_events()`；
  [engine.py](../src/backtest/engine.py) `_process_bar()`；
  [broker.py](../src/backtest/broker.py) `match_bar()`。
- 假设：13:00–15:00 的分钟 Bar 都可以按区间起点开盘价成交，没有收盘集合竞价阶段。
- 构造验证：14:57 开始的 Bar，在其它状态及数量合法时允许成交 100 股，成交时点按 14:57 记录。
  [上交所通知](https://big5.sse.com.cn/site/cht/www.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20180806_4607055.shtml)
  明确股票自 2018-08-20 起在 14:57–15:00 采用收盘集合竞价。
- 影响：可能在竞价完成前虚构成交、价格和持仓变化。
- 应验证：真实 14:56–15:00 数据及竞价前后订单，区分交易所、日期与频率。
  不能把全部历史交易时段统一截到 14:57，也不能因保留 15:00 收盘 Bar 就宣称竞价撮合已正确。

### AUD-007：已知无涨跌幅限制被等同于允许市价申报（P1，规则对照与构造复现）

- 位置：[broker.py](../src/backtest/broker.py) `_executable_quantity()`、`_known_price_limits()`；
  [trading_rules.py](../src/backtest/trading_rules.py) 34 行。
- 假设：`price_limit_status="unlimited"` 加不停牌就允许成交。引擎目前只提供市价数量订单，
  却没有另行核对该市场、该日是否接受这种申报。
- 构造深圳证券、连续竞价时点和明确无限制状态，代码允许 100 股成交。
  [深交所 2026 版规则](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)
  第 3.3.5 条要求市价申报用于有价格涨跌幅限制证券的连续竞价；第 10.9 条规定该版自
  2026-07-06 生效。本项规则冲突仅按该已核实版本判断，不倒推所有历史版本。
- 影响：可能在不接受市价申报的交易日生成成交。它不同于 BT-020 的未知状态误放行。
- 应验证：深圳新股无限制日市价单拒绝；其它市场、历史日期单独核实适用规则。

### AUD-008：早期北交所过户费套用了沪深标准（P2，规则对照与构造复现）

- 位置：[broker.py](../src/backtest/broker.py) `_fees()`，374 行；
  [trading_rules.py](../src/backtest/trading_rules.py) 北交所起始日期。
- 假设：同一天所有 A 股市场过户费相同。费用函数没有证券或交易所参数，2022-04-29 前统一
  使用成交额的 0.02‰，但已允许北交所 2021-11-15 起的订单。
- [券商官方执行公告](https://www.xcsc.com/main/a/20220429/1022871784.shtml)记载调降前北京 A 股
  为 0.025‰，沪深为 0.02‰；2022-04-29 起统一为 0.01‰。中国结算原链接本次跳转首页，
  不声称已读取其原始页面。
- 构造 2022-04-28 成交额 100 万元，代码过户费 20 元，北京市场应为 25 元。
- 影响与验证：北交所开市至 2022-04-28 的费用、现金和净值偏差；补三市场在 4 月 28/29 日的边界案例。

## 二、仍待核实的外部契约

### AUD-009：到区间结束时，已收到的最后一版是否就是完整 Bar（P1）

- 位置：[base.py](../src/qmt_protocol/base.py) `BarQuote`；
  [adapters.py](../src/market_data/adapters.py) `QmtAdapter.intraday_bars()`。
- 当前只检查 `interval_end <= as_of`，接收模式另检查 `received_at <= as_of`，没有源收线标志。
  固定快照模式还会合并下载与推送，优先取有较晚接收时间的推送版本。
- 尚缺证据：同标签是否反复更新、最后一版何时到达、临时版本能否在无后续回调时被误当成
  完整价格，以及推送版本能否覆盖更完整的下载行。结束标签本身不能回答这些问题。
- 应验证：盘中保存同一 Bar 的全部原始版本，跨分钟、午休与收盘边界，对照源 tick 和稍后下载的
  最终 OHLCV；不能拿当前构造测试或盘后零推送当作源协议证据。

### AUD-010：回调列表最后一行是否总是市场时间最新的行情（P2）

- 位置：[service.py](../src/qmt_agent/service.py) `_on_stock_quotes()`，415 行。
- 当前 `rows[-1]` 更新最新值缓存，更晚收到的旧行情也会覆盖缓存。
  构造 `time=[2000,1000]` 时缓存结果为 1000，仅证明条件行为，未发现真实倒序样本。
- [XtData 订阅说明](https://dict.thinktrader.net/nativeApi/xtdata.html#订阅单股行情)给出回调列表格式，
  本轮没有查到能依赖的排序与跨回调单调性保证。
- 应验证：首次订阅、重连与补送的原始列表；明确接口要表达“最后到达”还是“最新市场时间”。

### AUD-011：09:30 开盘记录与发布窗口能否推广到全部 QMT 分钟来源（P2）

- 位置：[clock.py](../src/backtest/clock.py) `opening_auction`；
  [adapters.py](../src/market_data/adapters.py) `intraday_bars()` 的 09:30 分支。
- 当前把结束标签 09:30 归入 09:15–09:30 发布窗口，只估值、不撮合；文档已经说明这是发布
  模型，不是宣称交易所开盘集合竞价在 09:30 结束，不能据此直接判为交易时间错误。
- 已有证据是本地单证券 1m 历史记录；其它周期及实时来源的独立 09:30 记录、量额包含范围、
  实际到达时间尚未逐一核实。1m/5m 边界回归使用的是构造输入。
- 应验证：分别采样各来源和周期的 09:24–09:36 行情，核对开盘记录与第一根正常 Bar 的量额，
  防止重复估算竞价数据或错误统计覆盖率。

### AUD-012：财务指标日期窗口是报告期还是公告日（P1）

- 位置：[sync.py](../src/tushare_data/sync.py) `sync_fina_indicator()`，327 行；
  日常财务回看窗口约 783 行。
- 当前按公告日理解 `fina_indicator_vip(start_date,end_date)`，日常仅回看最近 10 天。
  [Tushare 财务指标说明](https://tushare.pro/document/2?doc_id=79)却将这两个参数定义为报告期
  开始和结束，并说明 VIP 参数一致。
- 尚缺证据：项目实际使用 quicksync 代理，未确认它是否改变过滤轴。因此能确认文档与代码
  理解冲突，尚不能声称实际代理已漏采。
- 潜在影响：四月披露的上年年报可能不在最近 10 天的报告期窗口，只能等月度回补。
- 应验证：以 `600519.SH / end_date=2025-12-31 / ann_date=2026-04-17` 这类已知行，分别用
  报告期窗口与公告日窗口只读查询实际代理，并检查翻页及增量覆盖。

## 三、不应混为未经验证缺陷的已声明模型

- 日线 16:05 可见、仅有公告日期时下一交易日 09:25 可见：是明确选择的回测可见性规则，
  不是承诺数据源在该秒实际发布。要做真实接收回放仍须另存原始到达时间。
- 滑点、容量、红利税近似、碎股舍入、显式退市核销：已声明的模型范围；没有新证据时不把
  “不够精细”写成未经验证的外部事实。
- QMT 股票历史量额、除权换算已有项目实机交叉验证记录；证据只覆盖记录的样本和接口，
  不自动推广到所有产品、周期和客户端版本。
- 稳定 `sid` 要求外部可信更码表；没有表时不猜更码关系，属于明确依赖。

建议先处理会放行错误成交或改变历史可见性的 AUD-001、003、006、007，随后补齐采集完整性
与行业版本。AUD-009、010、011 应共用一次盘中原始采样验证。以上事项没有在本轮顺带实现，
后续修复应继续逐项验证、独立提交。
